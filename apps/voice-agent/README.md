# SiteLog voice agent

The phone and **Talk now** channel (spec §4.2, §9.4): a Python LiveKit Agents worker that takes a site manager's report by voice and talks to `field-api`'s `/voice/*` routes only. Python 3.12 with [uv](https://docs.astral.sh/uv/); outside the pnpm workspace.

## Layout

| Path                                         | What                                                                                                                                            |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `contract/*.json`, `copy/*.json`             | Generated by `pnpm voice:contract` from `packages/shared` (W3-01). Never edit by hand; the agent loads them, it holds no copy of a schema.      |
| `src/sitelog_voice/agent.py`                 | Entrypoint (`server`, one job per call room): `calls/start`, `get_context`, the disclosure first, then `ReportAgent`.                           |
| `config.py`                                  | Env (§5.1) with pydantic-settings; secrets never print. Model names from env (`CLAUDE_MODEL_FAST`) only.                                        |
| `session.py`                                 | `CallState`, the system prompt per language, the live providers per call language (Deepgram, Claude, Aura-2 / Azure, Silero, turn detector).    |
| `dialog.py`                                  | §7.3 as a pure state machine (states, 8 s silence, 10/12 min, two failures → fallback).                                                         |
| `tools.py`                                   | The §9.4 tools (plus `pick_site`) as `@function_tool`s; code, not the model, supplies the transcript, the utterance and the read-back revision. |
| `field_api.py`, `contract.py`                | httpx client (bearer + `X-Call-Token`, one retry on 5xx or transport errors, never on 4xx), both ways validated against `contract/`.            |
| `copy.py`, `prompts/`                        | Spoken lines from `copy/`; the §9.4 dialog policy verbatim per language (a test compares it with the spec).                                     |
| `redact.py`, `observability.py`              | Phone numbers out of every model request, log line and Sentry event (§10.12); Sentry tagged `service: voice-agent`.                             |
| `recording.py`, `voicemail.py`, `metrics.py` | Interfaces for W3-12 (dual-channel recording) and W3-17 (answering machines); the `end_call` metrics.                                           |
| `tests/fakes/`                               | `FakeFieldApi` (respx, validates every request and answer against `contract/`), `FakeLLM` (replays recorded turns).                             |

## Commands

From the repo root: `pnpm voice:test` (ruff, ruff format check, pyright, pytest; no key, no network: `pytest-socket` blocks it) and `pnpm voice:console` (by hand, needs the `lk` CLI and the keys).

In this directory: `uv sync` once, then `uv run pytest`, `uv run ruff check`, `uv run pyright`.

## Environment

`FIELD_API_URL`, `VOICE_AGENT_TOOL_SECRET`, `LIVEKIT_URL` / `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` / `LIVEKIT_AGENT_NAME`, `DEEPGRAM_API_KEY`, `STT_MODEL`, `TTS_VOICE_EN` / `TTS_VOICE_ES` / `TTS_VOICE_TR`, `AZURE_SPEECH_KEY` / `AZURE_SPEECH_REGION`, `ANTHROPIC_API_KEY`, `CLAUDE_MODEL_FAST`, `SENTRY_DSN`, `SENTRY_ENVIRONMENT`. A local run reads the root `.env`, then `apps/voice-agent/.env` (its values win). Tests read neither.

Deploying (`lk agent create` / `lk agent deploy`, the Dockerfile here) is an owner-approved hand step (W3-16), never CI.
